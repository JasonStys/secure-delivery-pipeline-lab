# Security reporting

This educational project is maintained by Jason Stys. For non-sensitive bugs, open a GitHub issue with a minimal synthetic reproducer. For vulnerabilities, use GitHub's private vulnerability-reporting facility if enabled; do not publish credentials, exploit targets, private logs or applicant/customer information. If private reporting is unavailable, contact the author through the professional profile linked in the README without including secrets.

Read [the threat model](docs/security.md) and [recovery runbook](docs/runbook.md). There is no promise of a response SLA, production certification, malware containment or protection from a compromised OS/GitHub account.

Do not scan third-party systems. All adversarial scenarios use authored fixtures or explicit verification of this repo's own public release assets.
